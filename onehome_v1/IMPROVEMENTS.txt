ONE HOME - CODE AND DATABASE CLEANUP

The QuickFix sample was used as a guide for simple PHP structure, readable indentation,
separate database actions, and prepared SQL statements. One Home keeps its existing
beginner-friendly procedural PHP + MySQLi structure because the whole project already
uses it. The sample's PDO class was not copied into only part of the project, which would
create two different database styles.

Changes made:
- Improved indentation and line breaks in key PHP files so code is easier to read.
- Kept database queries parameterized with prepared statements.
- Improved booking date and time validation.
- Improved image upload checks: actual image type, 2 MB limit, safe generated filename,
  writable upload folder, and upload failure feedback.
- Set the MySQL connection character set to utf8mb4 and kept connection errors clear.
- Added useful database indexes for common user, booking, and review lookups.
- Added missing foreign keys from reviews to the customer and employee user records.
- Added database checks for non-negative prices/payments and ratings from 1 to 5.
- Updated demo upcoming booking dates so the pending/confirmed examples are not already
  in the past.
- Kept all six database tables because each one is used by the current application:
  users, services, employee_services, bookings, payments, and reviews.

Important:
- Importing database/one_home.sql drops and recreates the project tables. Back up any
  existing database data before importing it again.
- Test with XAMPP Apache and MySQL/MariaDB. The database schema uses CHECK constraints;
  use a current MySQL or MariaDB version that enforces them.
- The card payment is only a demonstration. It does not charge a real card.

UI POLISH (November 2026)
- Replaced the administrator's long top navigation with a grouped sidebar.
- Added a mobile sidebar menu and responsive customer/employee navigation.
- Simplified the admin dashboard to four key metrics, pending actions, and six recent bookings.
- Restyled Users, Services, Bookings, Payments, Reviews, and Reports for clearer reading.
- Updated customer and employee dashboards with simpler layouts and clearer next actions.
- Added shared typography, spacing, cards, tables, form controls, and status styling.

Administrator account management
- Added an administrator-only page to create another administrator account.
- Added an Administrators tab under Users.
- Public registration still only accepts customer or employee accounts.
- New administrator creation uses server-side role assignment, password hashing, input validation, and a one-time form token.

URL AND PAGE ACCESS PROTECTION (November 13, 2026)
- Confirmed all 49 administrator, employee, and customer pages load the shared auth file
  and require the matching account role before showing page content.
- Strengthened the shared login/session check so account status and role are read from
  the database for every request; URL parameters cannot set the user's role.
- Added a dedicated session cookie name, HTTP-only and SameSite settings, and Secure
  cookies when the site is accessed through HTTPS.
- Added no-cache headers to protected pages to reduce private-page display after logout.
- Protected the profile action handler against direct use by inactive accounts.
- Added Apache rules to deny direct browser access to includes/ and database/, and to
  prevent PHP/script execution inside uploads/.
- Added SECURITY_ACCESS.md with the role access rules and deployment notes.

Note: URLs can still be copied. The security control is that the server checks the
active login, role, and record ownership whenever the copied URL is opened. Users with
the correct role and active session can still navigate directly to pages they are
permitted to use.
